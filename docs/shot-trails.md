# Shot trails and retro skies

`Scripts/lib/shot-visuals.ts` observes native projectile launches, post-simulation
snapshots and end events. It never changes shell positions, velocities, body
materials, weapon configuration or damage. Root shots, split warheads, barrages
and death volleys retain their original owner color.

## Persistent smoke

`Game/shot-trails.json` selects one gas for each roster color. Each gas uses
three high-contrast native noise bands: dark ink, the tank color and a pale
highlight. The texture anchor keeps the noise attached to each particle.
Puff shapes, gentle diffusion and native trail rendering soften the stroke as
it spreads. The gas has no lifetime expiry or opacity fade, so emitted particles
remain in the world as they drift and spread.

Emission samples the segment between successive actual projectile positions,
with two-pixel spacing and a four-pixel alternating lateral spread. A shared
budget permits at most 64 spray points, each containing four particles, per
simulation tick. Large volleys rotate their first serviced shot and thin smoke
evenly. Held shots, unchanged snapshots and paused games emit nothing. Native
particle admission can refuse cosmetic particles without interrupting combat.

`assets/native/elements/TANK_INK_VAPOR.json` supplies the nonflammable, silent gas
properties. The sixteen palette variants are generated by
`node tools/shot-visuals.cjs build`; install them with
`node tools/records.cjs elements`. Native `fireLife: 0` disables expiry, including
outside the simulation window. The gas has no reaction rules, damage or lights.
Native chunk storage preserves it with the rest of the battlefield; a new round
starts a fresh world.

## Persistent paths

`node tools/shot-visuals.cjs install` creates **Shot paths**, an unlit raster layer
above the foreground. Paths use the tank's solid color. The game records actual
positions, including bounces, and batches short polylines every quarter-second.
The end event closes the final segment. Native vector raster operations write
only this layer; they neither paint elements nor alter terrain collision.

A single asynchronous writer sends bounded regions to the native terrain-work
queue. The pending queue holds at most 2,048 strokes; refusal or overflow is
logged without stopping the match. Save waits for queued drawing; instant Quit
still discards unsaved progress. Completed lines belong to native raster chunks,
so normal world persistence owns their storage. A new round starts with an empty
layer from the template.

Raster drawing currently uses `talus.world.terrainWork` with vector raster
output. That API still acquires a simulation region and captures terrain before
committing; it is not a direct raster-only write. Measure its cost during live
acceptance before treating the drawing path as inexpensive.

## Retro skies

`node tools/retro-skies.cjs build` generates sixteen 480×270 pixel skies:
24-step gradients, giant low suns, cratered moons and sparse stars. The palette
and star placement are deterministic. Assets are native background records in
`assets/native/backgrounds/`; `install` saves them to the native library.
It also binds the default sunset to the authored background cells for the editor
preview. `node tools/retro-skies.cjs preview` updates that binding independently;
terrain and custom vertical background bands are preserved.

`Biomes/biomes.json` lets the engine choose a sky from the world seed. Reusing a
seed repeats its background; new round seeds can select another. Each biome
references the same daylight lighting preset, keeping the playfield bright even
under a moonlit sky. The single fitted background layer stays fixed in the
viewport as the camera follows high shots. It needs no particle simulation or
additional terrain generation.

If the sky is blank, enable **Show parallax background** in the editor's status
bar (Cmd/Ctrl+P). This display preference also applies when testing a game from
that editor profile; the background assets can be installed while rendering is
disabled.

After installing the assets, sync the maintained world files and export the
project. Validate two simultaneous tank colors, persistent smoke and lines
across a camera round trip, and sky selection in a real CPU game. Keep the
simulation-rate checks in [simulation-performance.md](simulation-performance.md).
